# Operating Systems
Why Do Modern Operating Systems Use Virtual Memory? | Beginner | Virtual Memory | Virtual memory gives every process its own address space, isolates programs from each other, and lets the kernel map physical pages lazily or share them. | It is the foundation of process isolation, memory-mapped files, and safe multitasking. | What does a page table entry need to record besides the physical address? | virtual-memory, paging, isolation
What Happens During a Context Switch? | Intermediate | Scheduling | The kernel saves the current thread's registers and state, selects another thread, and restores its context. Caches and translation buffers may remain cold for the newcomer. | Context switches explain the real cost of too many threads or chatty blocking calls. | Why can a context switch cost more than the register save itself? | context-switching, scheduling, performance
How Does a Scheduler Decide What Runs Next? | Intermediate | Scheduling | Schedulers balance latency, throughput, fairness, and priorities using run queues and heuristics. The right policy depends on whether work is interactive or batch. | Misunderstood scheduling leads to latency spikes that look like application bugs. | What fairness guarantee does a scheduler like CFS actually provide? | scheduling, fairness, latency
Why Are Page Faults Expensive? | Beginner | Virtual Memory | A page fault traps into the kernel, which must locate or create the page, potentially read from disk, update mappings, and resume the faulting instruction. | Faults connect memory pressure directly to application latency and system stability. | What is the difference between a minor fault and a major fault? | page-faults, memory, storage
How Do Copy-on-Write Semantics Save Memory? | Intermediate | Virtual Memory | Forked processes initially share physical pages marked read-only. The kernel copies a page only when one process writes, avoiding eager duplication. | Copy-on-write is behind fast process creation, snapshots, and some container image layers. | Why can long-lived forked services gradually duplicate large amounts of memory? | copy-on-write, fork, memory
What Makes a Race Condition So Hard to Reproduce? | Intermediate | Concurrency | Races depend on precise interleavings of threads and timing. Small changes in load, scheduling, or logging alter which order occurs. | The bugs that are hardest to reproduce are often the ones most likely to reach production. | How could you make a race easier to observe without changing the code's behavior? | race-conditions, concurrency, debugging
How Does the Kernel Enforce Isolation Between Processes? | Advanced | Kernels | Hardware privilege levels, page permissions, and system-call boundaries prevent user code from directly touching other processes or devices. | Isolation is the security property that makes running untrusted software possible. | What happens at the boundary when a process requests a privileged operation? | isolation, kernel, security
Why Can a Full Disk Stall an Entire System? | Advanced | File Systems | Writes, logs, package updates, and even memory reclaim may need disk space. When allocation fails, unrelated processes can block or crash. | Capacity planning is an availability concern, not merely an operations chore. | Which kernel and application paths still need disk space during memory pressure? | file-systems, disk, availability
How Do Memory-Mapped Files Blur Storage and Memory? | Intermediate | File Systems | mmap maps file pages into a process's address space, so reads and writes become memory accesses backed by page cache and writeback. | It is a core technique in databases, search engines, and high-performance loaders. | When is mmap faster than read and write, and when does it hurt? | mmap, page-cache, io
