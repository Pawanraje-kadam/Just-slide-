# Programming Language Design
How Do Type Systems Prevent Entire Classes of Bugs? | Intermediate | Type Systems | Types encode invariants about values and operations, letting a checker reject programs before they run. Stronger types shift error detection earlier and constrain how data can flow. | Type design is interface design, and it changes what mistakes are even expressible. | What invariant could you encode in a function signature instead of documenting it? | type-systems, safety, invariants
Why Does Ownership-Based Memory Management Work? | Advanced | Memory Management | Ownership assigns each value a responsible scope and tracks moves and borrows at compile time, eliminating many use-after-free and data-race errors without a garbage collector. | It shows how language rules can enforce memory safety with predictable runtime behavior. | What restrictions does borrowing impose, and why are they necessary? | ownership, rust, memory-safety
How Do Garbage Collectors Trade Throughput for Latency? | Advanced | Memory Management | Collectors reclaim unreachable memory automatically, but their work competes with the application. Generational, concurrent, and incremental designs shift pauses versus overhead. | Runtime pauses are a language-level design choice that affects system latency budgets. | Why can a concurrent collector still produce long tail latencies? | garbage-collection, latency, runtimes
Why Do Undefined Behaviors Make Compiler Optimizations Dangerous? | Advanced | Semantics | Languages that declare certain operations undefined let compilers assume they never happen. That assumption enables optimization but can turn latent bugs into unpredictable behavior. | Code that appears to work can be silently rewritten once optimization changes. | How does signed overflow becoming undefined enable loop optimizations in C and C++? | undefined-behavior, compilers, c-cpp
What Are the Trade-Offs Between Static and Dynamic Typing? | Beginner | Type Systems | Static typing catches errors early and supports tooling, while dynamic typing allows rapid exploration and runtime flexibility. Both can be sound or unsound depending on implementation. | The debate is really about when feedback arrives and how much freedom the language allows. | Which errors do you want the compiler to catch rather than tests? | static-typing, dynamic-typing, trade-offs
How Do Async Runtimes Schedule Tasks? | Advanced | Concurrency Models | Async runtimes multiplex many tasks onto a small pool of threads. Futures are polled when ready, and blocking a worker thread stalls every task assigned to it. | Misusing blocking calls inside async code is a common production failure. | Why can one blocking call inside an async handler freeze unrelated requests? | async, runtimes, concurrency
What Makes a Language's Error Model Ergonomic? | Intermediate | Semantics | Exceptions, result types, and error unions distribute responsibility differently. Good models make failure visible without burying the happy path in boilerplate. | Error handling shapes every API and often decides whether failures are ignored. | How does a result type change the way callers handle ordinary failures? | error-handling, api-design, languages
Why Do Immutable Data Structures Help Reasoning? | Beginner | Semantics | If a value never changes after creation, it can be shared safely across threads and compared by identity or value without hidden transitions. | Immutability eliminates whole categories of aliasing bugs at the cost of allocation. | What does structural sharing let an immutable collection do efficiently? | immutability, concurrency, data-structures
How Does Structural Typing Differ from Nominal Typing? | Intermediate | Type Systems | Nominal systems match types by declared name and hierarchy, while structural systems match by shape. Each makes different refactors and accidental matches easy. | The choice affects whether unrelated types can be interchangeable and how APIs evolve. | What are the risks of two unrelated structural types accidentally satisfying each other? | structural-typing, nominal-typing, types
