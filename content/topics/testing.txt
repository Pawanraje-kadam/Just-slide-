# Testing & Verification
Why Is a Flaky Test Worse Than a Missing Test? | Intermediate | Flaky Systems | A test that sometimes fails teaches the team to ignore failures, including real ones. It consumes trust and retry infrastructure without providing reliable evidence. | Unreliable tests slowly destroy the value of the entire suite. | What non-determinism in a test makes it flaky rather than genuinely revealing a race? | flaky-tests, ci, reliability
What Makes Property-Based Testing Effective? | Intermediate | Test Design | Property-based testing generates many inputs and checks invariants that should hold for all of them, then shrinks failures to minimal reproductions. | It explores edge cases a person would not think to write. | Which property of a sorting function could you test without hardcoding examples? | property-based-testing, invariants, fuzzing
How Does Fuzzing Find Bugs Tests Miss? | Intermediate | Fuzzing | Coverage-guided fuzzers mutate inputs and keep those that reach new code paths, exploring deep states over time. They excel at crashes and memory errors. | Security-critical parsers and protocols rely on fuzzing to find the unexpected. | Why does code coverage feedback make a fuzzer more effective than random input? | fuzzing, coverage, security
Why Is One Hundred Percent Coverage a Weak Goal? | Beginner | Test Design | Coverage measures executed lines or branches, not whether assertions would catch wrong behavior. Tests can cover code without checking anything meaningful. | Chasing a number can produce tests that execute everything and verify nothing. | How would you judge whether a covered branch is actually tested? | coverage, test-quality, metrics
What Makes a Mock Dangerous? | Intermediate | Test Design | Mocks replace real collaborators with assumptions written by the test author. When the real behavior diverges, tests remain green and hide integration failures. | A mock tests your understanding of a dependency, not the dependency itself. | When should a test use a real dependency instead of a mock? | mocking, integration-tests, isolation
How Do Engineers Test Distributed Systems? | Advanced | Formal Methods | Deterministic simulation, fault injection, and invariant checking expose timing-dependent behavior that unit tests never reach. Reproducing failures requires controlling time and failures. | The bugs that matter most occur across process boundaries and under partially failed conditions. | How would you simulate a network partition in a test harness? | distributed-testing, simulation, fault-injection
What Makes a Regression Test Durable? | Intermediate | Test Design | A durable regression test targets observable behavior rather than implementation details, so it survives refactors while still catching the original bug. | Tests coupled to internals create maintenance work and get deleted, losing the protection they offered. | Which part of a test would need updating after a harmless refactor? | regression-tests, refactoring, test-design
How Does Formal Verification Differ from Testing? | Advanced | Formal Methods | Verification proves properties over all possible behaviors within a model, while testing samples specific executions. Proofs require precise specifications and abstraction. | Verification can find rare failures that sampling misses, but only for properties you state correctly. | What kind of bug would testing likely miss that a model checker could find? | formal-verification, model-checking, specifications
Why Are Integration Tests Usually Slower? | Beginner | Test Design | Integration tests exercise real databases, networks, and services, which adds setup, I/O, and coordination overhead compared with in-process unit tests. | The test pyramid is really a feedback-speed trade-off. | What integration boundary could you test with a lightweight substitute? | integration-tests, feedback, test-pyramid
