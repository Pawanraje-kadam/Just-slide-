# Developer Tools & Build Systems
How Do Static Analyzers Find Bugs Without Running Code? | Intermediate | Static Analysis | Analyzers build abstractions such as control-flow graphs and type information, then apply rules or data-flow analyses to detect patterns that likely indicate defects. | Fast local feedback prevents whole classes of bugs from reaching review. | What false positive would a static analyzer produce when it cannot see a dynamic call? | static-analysis, dataflow, tooling
Why Can a Build Produce Non-Reproducible Artifacts? | Intermediate | Reproducibility | Timestamps, paths, randomized ordering, and environment-dependent dependencies leak into outputs. Without hermetic inputs, the same source can produce different binaries. | Reproducibility enables verification, caching, and trust in distributed builds. | Which common build inputs introduce nondeterminism into an artifact? | reproducible-builds, determinism, build
How Does Incremental Compilation Save Time? | Beginner | Caching | An incremental build reuses prior outputs for units whose inputs did not change, tracking dependencies to decide what must rerun. | The inner loop speed affects how much developers experiment and refactor. | What dependency information must be tracked to know a module is unchanged? | incremental-builds, caching, compilers
Why Do Monorepos Need Careful Build Graphs? | Advanced | Build Systems | A monorepo changes only a small part of the codebase per commit, so tools must compute affected targets and cache results across projects without missing hidden dependencies. | Without a build graph, a monorepo becomes a slow pile of unrelated projects. | How would you determine which tests to run after changing a shared utility? | monorepo, build-graph, caching
What Makes a Code Formatter Opinionated by Design? | Beginner | IDE Infrastructure | A formatter removes style decisions by defining one canonical output. This reduces review noise and avoids configuration debates that add no product value. | Consistency helps humans and automated tooling read diffs. | Why does formatting churn make code review harder? | formatting, tooling, code-review
How Does the Language Server Protocol Power Editor Tooling? | Intermediate | IDE Infrastructure | LSP standardizes requests for completion, diagnostics, and navigation between editors and language servers, so tooling is implemented once per language rather than once per editor. | Protocol design explains why editor features are now broadly available across tools. | What information does an editor need to render a hover type signature? | lsp, editors, protocols
Why Is a Hermetic Build a Strong Guarantee? | Advanced | Reproducibility | A hermetic build declares and isolates every input, including compilers, environment, and dependencies, so outputs depend only on the declared sources. | It makes caching safe and results verifiable across machines. | What would you need to isolate to make a build hermetic? | hermetic-builds, reproducibility, isolation
What Makes a Watch Mode Efficient? | Intermediate | Build Systems | A watch mode must detect relevant file changes, invalidate only affected outputs, and avoid rebuilding the world on every keystroke while keeping state consistent. | Developer feedback speed is often decided by these details. | How would you avoid triggering a full rebuild when a comment changes? | watch-mode, incremental-builds, developer-experience
Why Are Diagnostics Only Useful If They Are Actionable? | Intermediate | Static Analysis | A warning must identify a real issue, explain why it matters, and suggest a fix. Unactionable warnings consume attention and get suppressed wholesale. | Bad diagnostics train developers to ignore good ones. | How would you decide whether a lint rule should be an error, warning, or suggestion? | diagnostics, linters, developer-experience
