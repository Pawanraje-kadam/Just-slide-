# Data Engineering
Why Is Backpressure Important in Data Pipelines? | Intermediate | Streaming | A pipeline stages produce and consume at different rates. Without backpressure, fast producers fill buffers and cause memory exhaustion, dropped data, or cascading failure. | Unbounded queues turn a throughput mismatch into an outage. | How would you apply backpressure from a slow sink all the way to the source? | backpressure, streaming, flow-control
What Makes a Data Pipeline Idempotent? | Intermediate | Pipeline Design | Rerunning a pipeline after failure must not duplicate rows or double-count aggregates. Idempotency requires deterministic keys, overwrite semantics, or transactional staging. | Retries are routine in data engineering, so non-idempotent jobs guarantee corrupted results eventually. | How would you make a daily aggregation safe to rerun for the same date? | idempotency, pipelines, batch
How Do Batch and Stream Processing Differ? | Beginner | Batch Processing | Batch processing operates on bounded chunks; stream processing handles unbounded events continuously. Latency, correctness, and state management differ accordingly. | Choosing the wrong model adds cost and complexity without matching the freshness requirement. | When does a five-minute micro-batch behave like a stream? | batch, streaming, latency
Why Does Late-Arriving Data Break Aggregations? | Advanced | Streaming | Events can arrive after a window is supposedly complete. Without watermarks or allowed lateness, results are emitted early and then silently become wrong. | Real-world streams are rarely ordered, even when the schema implies they are. | How would you update a window result when a late event changes the correct answer? | late-data, watermarks, streaming
What Makes a Data Warehouse Schema Evolvable? | Advanced | Analytics Infrastructure | New sources and changing product assumptions alter columns and grain. Schemas that force destructive migrations create fragile pipelines and lost history. | Data outlives the applications that produced it, so schema decisions persist. | How does a columnar warehouse handle adding a nullable field safely? | schema-evolution, warehouse, data-modeling
How Do Engineers Detect Silent Data Corruption? | Advanced | Data Quality | Corruption often does not raise errors: values are plausible but wrong. Detection needs distribution checks, reconciliation, and source-to-target assertions. | Silent errors are worse than crashes because dashboards and decisions continue with bad data. | What checks would catch a column shifted by one row? | data-quality, validation, reconciliation
Why Does Watermarking Matter in Event-Time Processing? | Advanced | Streaming | Watermarks estimate when earlier events are unlikely to arrive, bounding how long state must wait for out-of-order data. They balance completeness against latency. | Using processing time when the business meaning is event time produces subtly wrong results. | What happens to window emissions when a watermark advances too aggressively? | watermarks, event-time, streaming
What Makes a Data Contract Useful? | Intermediate | Data Quality | A data contract specifies schema, semantics, freshness, and ownership between producers and consumers, making breaking changes visible before dashboards fail. | Data teams often discover upstream changes only after downstream reports break. | Which fields of a contract enforce freshness rather than just structure? | data-contracts, governance, ownership
Why Do Small Files Hurt Data Lake Performance? | Intermediate | Analytics Infrastructure | Each file adds metadata, listing, and open costs. Query engines spend more time on file overhead than reading actual data when files are numerous and tiny. | Ingestion patterns that create many small files can make a lake unusable at scale. | How would you compact small files without breaking incremental readers? | data-lakes, compaction, performance
