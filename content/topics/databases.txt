# Databases & Storage Engines
Why Can an Index Slow Down Write-Heavy Workloads? | Intermediate | Indexing | Every index must be updated on insert, update, and delete. More indexes mean faster reads but more write amplification, memory pressure, and lock work. | Index design is a workload trade-off, not a default optimization. | How would you decide which indexes to remove from a write-heavy table? | indexes, write-amplification, tuning
How Does Multi-Version Concurrency Control Work? | Advanced | Transactions | MVCC keeps multiple row versions so readers can see a consistent snapshot without blocking writers. The cost is version storage and garbage collection. | It explains how databases offer isolation with high concurrency, and why long transactions create bloat. | Why do long-running read transactions cause cleanup problems in MVCC systems? | mvcc, transactions, concurrency
Why Can a Query Planner Choose a Bad Execution Plan? | Advanced | Query Processing | Planners estimate cardinality and cost from statistics that can be stale, skewed, or misleading. A wrong estimate at one join cascades through the plan. | The database may be correct yet still choose an algorithm that is orders of magnitude slower. | How do cardinality misestimates compound across a multi-way join? | query-planner, cardinality, optimization
What Causes Write Amplification in Storage Engines? | Advanced | Storage Layouts | A logical write may trigger multiple physical writes through logging, compaction, and replication. The ratio between them determines endurance and throughput. | Flash wear and sustained write performance both depend on this ratio. | How does an LSM tree amplify writes during compaction? | write-amplification, lsm-trees, storage
How Do Replication Lag and Read Consistency Interact? | Intermediate | Replication | Replicas apply changes after the primary, so reads from a replica can be stale. Read-your-writes guarantees require routing or session tracking. | Users notice inconsistency when their own update disappears on refresh. | How would you guarantee read-your-writes across a pool of replicas? | replication, consistency, read-replicas
When Is Event Sourcing Worth the Complexity? | Advanced | Storage Layouts | Event sourcing stores state transitions as an append-only log and derives current state by replay. It offers auditability and temporal queries at the cost of more operational machinery. | It is often adopted for philosophical reasons when a simpler audit table would suffice. | What query and retention requirements would justify event sourcing over a mutable schema? | event-sourcing, audit, architecture
Why Do B-Trees Dominate Disk-Based Indexes? | Intermediate | Indexing | B-trees keep many keys per node, matching disk page sizes and keeping depth low. Range scans are efficient because leaves are linked in order. | Understanding the structure explains index behavior for both lookups and scans. | Why is a high fanout more important than a shallow binary search tree on disk? | b-trees, indexes, storage
How Does a Write-Ahead Log Protect Data After a Crash? | Intermediate | Transactions | Changes are first appended to a durable log, then applied to data pages later. Recovery replays committed log records and discards incomplete ones. | WAL is the mechanism behind atomicity and durability in most transactional databases. | What does a database do during recovery if a crash happens mid-checkpoint? | write-ahead-log, durability, recovery
What Makes the N+1 Query Problem Expensive? | Beginner | Query Processing | Fetching a list and then querying once per item multiplies round trips and database work, even when each individual query is fast. | It is a common cause of slow application pages that look fine in isolated query timing. | How would you restructure a list page to avoid N+1 queries? | n+1, orm, performance
Why Is Serializable Isolation So Costly? | Advanced | Transactions | Serializable isolation must prevent all interleavings that violate serial order, often using locking, predicate checks, or retry-heavy optimistic validation. | Strong isolation protects correctness but can turn contention into aborts and latency. | How does serializable snapshot isolation detect a dangerous write skew pattern? | isolation, serializability, transactions
