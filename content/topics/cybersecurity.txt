# Cybersecurity
Why Does Threat Modeling Improve Software Design? | Beginner | Threat Modeling | Threat modeling asks what can go wrong, who would cause it, and what defenses exist before code is written. It surfaces design flaws that testing rarely catches. | Security added after implementation is often limited to patching symptoms. | What trust boundaries would you draw for a feature that accepts file uploads? | threat-modeling, security-design, risk
How Do Authentication and Authorization Differ in Real Systems? | Beginner | Identity | Authentication verifies identity; authorization decides what that identity may do. Confusing them leads to checks that prove who someone is but not whether they should act. | Many access-control bugs are authorization failures hiding behind a successful login. | Where should authorization checks live so every access path enforces them? | authentication, authorization, access-control
What Makes Memory-Safety Vulnerabilities So Persistent? | Intermediate | Defense in Depth | Languages with manual memory management allow out-of-bounds access, use-after-free, and type confusion. These bugs are easy to introduce and often exploitable. | Memory safety remains one of the largest sources of serious vulnerabilities in production software. | How do modern mitigations change the exploitability of a use-after-free? | memory-safety, exploitation, vulnerabilities
How Can Secret-Management Mistakes Compromise Production Systems? | Intermediate | AppSec | Secrets committed to repositories, baked into images, or logged can leak through paths teams forget to monitor. Rotation and least privilege limit the damage. | Credential exposure often converts a minor bug into full system compromise. | What would an attacker do with a leaked database password from a CI log? | secrets, ci-cd, incident-response
Why Does Defense in Depth Rarely Fail at One Layer? | Intermediate | Defense in Depth | Layered controls assume each can fail, so a mistake must bypass several independent protections to become serious. Independence is the hard part. | Overlapping controls can look thorough while sharing the same blind spot. | Which of your security layers would still work if the perimeter were fully compromised? | defense-in-depth, security-design, resilience
What Makes a Privilege-Escalation Bug So Dangerous? | Advanced | Exploitation | A low-privilege process that gains higher rights can read data, modify code, or move laterally across a network. The initial foothold becomes a full breach. | Most severe incidents involve escalation after a small initial compromise. | What design choices would contain an attacker who already controls one process? | privilege-escalation, least-privilege, containment
Why Are Injection Vulnerabilities Still Common? | Beginner | AppSec | Injection occurs when untrusted input is interpreted as code or structure, from SQL to shell commands to templates. Mixing data and syntax is the root cause. | The vulnerability class is decades old, yet new frameworks and protocols keep recreating it. | How does parameterization separate data from SQL syntax? | injection, input-validation, appsec
How Do Security Teams Think About Attack Surface? | Intermediate | Threat Modeling | Attack surface is every interface, credential, dependency, and configuration an attacker can reach. Reducing it shrinks the number of paths requiring defense. | You cannot defend what you do not know is exposed. | How would you inventory the reachable entry points of a web application? | attack-surface, inventory, security
What Makes a Zero-Trust Architecture Different? | Advanced | Identity | Zero trust removes the assumption that internal networks are safe, requiring continuous verification and least-privilege access for every request. | Remote work and cloud boundaries make perimeter thinking increasingly fictional. | What has to be true about identity and policy for zero trust to be practical? | zero-trust, identity, architecture
